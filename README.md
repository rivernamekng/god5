# FIVE LOGIC

ゴッドファイブ系の数字推理ゲームを遊べるスマホ向けWebアプリです。

- 1人 vs CPU
- 人間2人のオンライン対戦
- 人間2人 + CPU の3人戦(2人がオンラインで参加し、CPUが3人目として自動参加)

URLを開くだけで遊べます。App Store等への公開は不要です。

## 遊び方の概要

各プレイヤーは5色(緑・桃・青・赤・橙)1枚ずつ、合計5枚を持ちます。自分の数字は自分には見えず、他プレイヤーの数字は見えます。手番では山から1枚公開し、場のコマを使って自分の手札を「分類」または「比較」で調べ、手がかりを積み重ねて自分の5枚を推理します。5つの数字を小さい順にすべて言い当てれば勝利(GOT FIVE)、外すと脱落します。

## プレイ画面の構成

実際のテーブルを自分の席から見た配置にしています。上から順に:

1. **相手のコマ**(数字が見えている) と、その相手が差し込んだコマ
2. **テーブル中央** — 5色の裏向きの山と、場に出ているコマ
3. **差し込まれたコマ** — 自分が調べた結果。文章ではなく、実際のコマを
   自分の5枚の「どの隙間に入るか」の位置へ差し込んで残す
   (比較の場合は、比べた1枚の真上に「=」「≠」付きで置かれる)
4. **自分のコマ**(数字は「?」) と、推理した数字を書き込むメモ欄
5. **推理ボード**(候補から外した数字をタップで消す。自分の端末のみ)
6. **GOT FIVE 宣言ボタン** — メモ欄に書いた5つの数字で宣言する

スマホでは推理ボードとGOT FIVEボタンまで含めて1画面に収まるようにしています。
勝敗が決まると結果が画面の前面に大きく出ます。「最終盤面を見る」で結果を閉じて
盤面を確認でき、右下の「結果を見る」でいつでも開き直せます。数字メモ欄は
ゲームが終わっても自分が書いたメモのまま残るので、真上に公開される実際の数字と
見比べられます。

詳しいルールはコード内コメントおよび`app.js`のロジックを参照してください。

## 必須のデプロイ手順

### 1. Supabase側でSQLを実行する(オンライン対戦を使う場合は必須)

`supabase.sql` の内容を Supabase プロジェクトの SQL Editor で実行してください。

**重要:** このバージョンでは同時書き込みの競合を防ぐために `revision` という列を
`godfive_rooms` テーブルに追加しています。過去にこのテーブルをすでに作成済みの
場合でも、`supabase.sql` は `create table if not exists` / `add column if not exists`
で書かれているため、そのまま再実行して問題ありません。

**この移行SQLを実行しないと、オンライン対戦(2人戦・3人戦)は動作しません**
(`revision` 列が存在しないため書き込みがエラーになります)。CPU戦(1人プレイ)は
Supabaseを使わないため、SQLを実行しなくても遊べます。

### 2. config.js を設置する

```js
window.SUPABASE_URL = "https://xxxxx.supabase.co";
window.SUPABASE_ANON_KEY = "sb_publishable_xxxxxxxxxxxxxxxx";
```

- 必ず **Publishable / anon key** を使用してください。
- `service_role` / secret key は絶対にフロントエンドに置かないでください。
- `config.js` を空のまま公開しないでください(オンライン対戦が使えなくなります。
  CPU戦は引き続き遊べます)。

### 3. Netlifyへデプロイする

このリポジトリはビルド不要の静的サイトです。`index.html` があるディレクトリを
そのままNetlifyにデプロイしてください。`netlify.toml` で `index.html` 等に
`no-cache` ヘッダーを付与しているため、スマホ側に古いHTML/JSが残りにくくなって
います。

**更新のたびに `index.html` 内の `?v=N` を上げてください**
(`styles.css?v=10`, `app.js?v=10` など)。バージョン文字列を変えないと、
一部のブラウザ/キャリアのキャッシュで古いJSが読み込まれ続けることがあります。

## モードについて

| モード | 説明 | Supabase |
|---|---|---|
| `cpu2` | 1人 vs CPU | 不要(ブラウザのlocalStorageのみ) |
| `online2` | 人間2人のオンライン対戦 | 必要 |
| `online3cpu` | 人間2人 + CPU の3人戦 | 必要(CPU操作はホスト側ブラウザが担当) |

3人戦のCPU操作はホスト(部屋を作った人)のブラウザが行います。ホストがページを
閉じている間はCPUの手番が進みません。

## 今回のアップデートで修正した主な不具合

- **同時書き込みの競合防止(revisionガード)**: 部屋への同時参加や、通信の
  タイミングによって古いstateが新しいstateを上書きしてしまう問題を、
  楽観的排他制御(`revision`列を使った条件付き更新+再試行)で修正しました。
- **Supabase読み込み失敗時にアプリ全体が起動しなくなる不具合**: CDNの読み込みに
  失敗しても(通信不安定・広告ブロッカー等)、CPU戦は問題なく遊べるように
  修正しました。
- **プレイヤー名のXSS脆弱性**: 対戦相手の名前を`innerHTML`にそのまま挿入して
  いた箇所をエスケープするよう修正しました。
- **再戦時に相手側の推理ボードの印が残ってしまう不具合**: 対局ごとに発行される
  `dealId` を推理ボードの保存キーに含めることで、ホスト・ゲスト双方の端末で
  再戦のたびに自動的にまっさらな状態になるようにしました。
- **固定表示の推理ボードが操作ボタンを覆い隠すレイアウト崩れ**:
  推理ボードを通常の並び(画面下部固定をやめる)に戻し、GOT FIVEボタンを
  最下部に置くことで、操作ボタンが隠れない構成にしました。
- 部屋が存在しない/満員/開始済みのエラーメッセージを区別して表示するように
  改善しました。

## 既知の制限事項

- オンライン対戦(2人戦・3人戦)の実機での同時接続テストは、このリポジトリの
  自動テスト環境からは実行できませんでした(サンドボックスのネットワーク制限に
  より実際のSupabaseプロジェクトへ到達できないため)。デプロイ後に一度、
  実機2台での部屋作成・参加・手番同期・GOT FIVE・再戦を確認してください。
- 全5色の山が同時に尽きるという極端なケース(通常のプレイでは起こり得ない
  ほど長期化した場合)への保護的な処理は入れていますが、実運用で発生した
  報告はありません。
